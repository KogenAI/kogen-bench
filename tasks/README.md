# Public task catalogue

125 task IDs are catalogued. Public prompts are present for 90 IDs; the following 35 records are metadata-only and have no public prompt: `elx-02-ingest-supervision`, `elx-03-fanout-timeouts`, `elx-04-queue-backpressure`, `elx-05-cache-single-flight`, `elx-06-command-runner`, `elx-07-cli-stats`, `elx-12-retry-api-deprecation`, `hp-syn-13`, `hp-syn-23`, `hp-syn-40`, `new-beltway-pipeline-deadline`, `new-trackline-bulk-transfer-outbox`, `rt-01`, `rt-02`, `rt-04`, `rt-05`, `rt-06`, `rt-08`, `syn-01-live-ticket-filters`, `syn-03-authz-cross-org-tickets`, `syn-06-migration-ticket-numbers`, `syn-10-tests-query-mutation`, `syn-13-bug-empty-filter-crash`, `syn-14`, `syn-14-bug-sla-business-hours`, `syn-15-validation-ticket-form`, `syn-17`, `syn-17-security-mass-assignment`, `syn-20-email-invite-flow`, `syn-23-csv-export`, `syn-24-csv-import`, `syn-26-archive-audit-log`, `syn-31-inbound-email-webhook`, `syn-33-stale-event-ordering`, `syn-40-reactions-and-mentions`.

Task definitions deliberately omit grading commands, sealed paths, and environment identities. `retired: false` is a maintenance default, not a verified admission claim; `retired_verified: false` preserves that uncertainty. Quarantine/admission must be checked before future use. The 65 Git base bundles and their manifest are in [`_bases/`](_bases/); 56 task records point to a bundle containing their exact recorded base commit. `base_missing: true` marks the other 69 records, including unknown or unavailable base revisions. Dependency caches are not bundled.

Task prompts are benchmark fixtures preserved as-run, not research narration or owner quotations. First-person wording inside a prompt is part of the task stimulus and is retained for provenance and reproduction.

Missing definitions may have a manifest-recorded base commit; this is labelled provenance, not a recovered public task contract. Short official-ledger IDs remain distinct until alias equality is checked. Prompt email examples and private paths are placeholders, so exact replay requires approved originals.

`used_in` means at least one captured delivery with this exact task ID in `results/run-records/index.json`, including ungraded deliveries. `graded_in` means the exact task ID has an official outcome row in `cells.jsonl`. `planned_in` means the task ID appears in a public planned-task listing, `PLAN.json`, or a table with a `Planned n` column. `round_page_mentions` preserves exact task-ID references on round pages without matching captured, graded, or plan evidence; `unverified_round_refs` preserves prior tags not corroborated by an exact ID in these sources. These fields distinguish activity without inferring a plan, delivery, or grade from an unverified label. The `documentary:<slug>` labels were removed because the [public source register](../sources/README.md) has no matching documentary entries.
