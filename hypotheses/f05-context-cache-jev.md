# F05 — Context, Jev and cache

Coverage: H51–H61. Context diagnostics, offline routing, request telemetry, and live task outcomes use different analysis units. The Wave B claim ledger is linked at [`results/claim-ledger.jsonl`](../results/claim-ledger.jsonl). Unreconciled numeric observations are explicitly marked **source-reported, not reproducible from public data**.

## Design implications

Keep request telemetry, offline context quality, route agreement, and scored Build outcomes in separate tables. Cache comparisons require a shared definition, fixed request denominator, model and effort, prefix/session policy, host/provider epoch, and exact request records. Context-packet comparisons require a matched baseline and report both packet cost and downstream task success.

## What this evidence does not show

The T98 smoke does not establish that a cache fix improves success, time, or cost. Historical cache-rate summaries are not denominator- or epoch-matched to T98. R54 does not demonstrate that handoff saves tokens or preserves success. Offline Jev agreement and partial Tidewave diagnostics do not establish live routing or context benefits. The available pages do not isolate language from cache, prompt, or human-steering differences.

## Smallest open tests

Publish raw per-request cache records and repeat the same request sequence before and after a fixed-affinity change, with a predeclared gate and identical accounting. For context, test a bounded packet against a no-packet control on matched failures, then grade final Builds and include packet-generation cost. For H61, rerun language arms with identical prompt, cache key, steering policy, model, and token accounting.
