# F06 Checks, review, and recovery

This page records evidence for H62–H74. The propositions below are hypotheses, not established findings. Published measurements remain attached to their individual runs and claim IDs. Where a B1 claim has no hypothesis mapping, it is cited as contextual evidence without changing that ledger mapping.

## Design implications

The public evidence supports treating test quality and review false blocks as risks to measure. It does not qualify a default review veto, a fixed list of fast checks, automatic test demotion, or an automatic contract-audit gate. Keep offline diagnostics, saved-candidate counterfactuals, and live Build outcomes separate.

## What this evidence does not show

It does not establish that a reviewer improves live acceptance, that additional checks preserve defect detection while reducing time, or that a recovery loop increases completion. Offline counts are not live Build rates. A candidate that passes a saved grading counterfactual is not an official round pass.

## Smallest open tests

Freeze a blinded set of true defects, valid alternatives, and passing controls; compare each proposed check or reviewer with a matched baseline; record exact case IDs, false accepts, false blocks, time, cost, and fresh confirmation outcomes. For H65 and H72, run a prospective recovery test that records process custody and stage transitions and counts Kogen-internal stops under the declared ITT rule.
