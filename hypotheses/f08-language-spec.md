# F08 Language and executable specification

This page records evidence for H91–H99. Language choice is a design decision informed by bounded observations; the available task cohorts do not establish a general language ranking.

## Hypotheses and current status

| ID | Falsifiable proposition | Current evidence status |
|---|---|---|
| H91 | A matched comparison can identify the best implementation language for the Kogen agent loop across task success, reliability, cost, and implementation time. | DESCRIPTIVE ONLY. Public cohorts are small and incomplete, and some original tasks have implementation confounds. |
| H92 | Rust has a better runtime and concurrency tradeoff than Elixir OTP when logic, prompts, and repair opportunities are equivalent. | NOT ESTABLISHED. The public comparison does not hold all of those factors constant. |
| H93 | Separating Mix applications into an umbrella makes tests and the workflow faster. | NOT ESTABLISHED. No before/after architecture comparison is identified. |
| H94 | Language-agnostic executable acceptance specifications preserve the same semantics across implementations. | PARITY METHOD, NOT EFFICACY. Conformance can test parity but does not show improved task completion. |
| H95 | Quint specifications written during planning improve Kogen or direct-model outcomes. | NOT ESTABLISHED. No controlled live comparison is identified. |
| H96 | Reviewing the translation from natural-language requirements into Quint catches omitted behavior. | NOT ESTABLISHED. No public translation-audit outcome is linked. |
| H97 | A fair language comparison holds tasks, prompts, model, effort, steering, grader, and repair loop constant. | METHOD REQUIREMENT. Existing language cohorts do not establish full parity. |
| H98 | Gleam should remain eligible until a defined matched-comparison rule supports excluding it. | NOT ESTABLISHED. No public inclusion-rule test or Gleam cohort is available. |
| H99 | Compile time, run wall time, token use, and task grade should all inform the language choice. | PARTIAL MEASUREMENT. Public timing and resource files exist, but their measurements are descriptive and do not by themselves rank full implementations. |

### Sol-medium language replication

The [language replication round](../rounds/lang-sol-replication/README.md) reports 27 new cells and 31 reused cells on six task identities. Raw combined results are Rust 18/20, Go 18/20, and TS-Bun 15/18. A post-hoc unweighted mean of the six task pass fractions is Rust 90.3%, Go 88.9%, and TS-Bun 83.3% ([CL-SOL-LANG-REPLICATION-POSTHOC-EQUAL-TASK](../results/claim-ledger.jsonl), **STATUS_ONLY**). The original equalization formula and scale for the four-pass threshold were not recorded; this sensitivity does not execute that branch. The claim is bounded to the selected Sol-medium replication cohort and does not establish a broad language ranking.

## Design implications

The public records support keeping the language cohorts separate and retaining a language choice as a bounded product decision. The original cohort is confounded; the fixed-skeleton rerun is a sensitivity check with failed admission controls; the extension is descriptive. Executable specs can test that implementations follow a defined contract, but parity is not evidence that one language or specification method improves agent outcomes.

## What this evidence does not show

These records do not show that Rust is broadly superior to Elixir, Go, TypeScript/Bun, or Gleam; that runtime or concurrency caused a pass-rate difference; or that Quint improves planning or task completion. The cost/time ledger is incomplete for several language cohorts, and compilation measurements are not a task-performance comparison.

## Smallest open tests

For language choice, freeze identical tasks, prompts, model and effort, tool access, retry policy, repair loop, grader, and resource accounting across stacks; include a predeclared rule for adding or excluding Gleam. For executable specifications, audit translation against blinded valid alternatives and omitted-behavior controls, then test whether the checks change live repair and completion outcomes.
