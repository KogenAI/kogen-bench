# Combined evidence and transient-output guidance

On ten small requests, the stored release reached 6 ready Intents and a candidate reached 5. One case changed from ready to not ready; there were no gains. Two unpatched repetitions reached 6 and 7, with two and three paired flips respectively. The candidate was dropped because the score fell and the stored comparison had a regression. No question was asked. This is a screen, not a qualified delivery change.

The single discordant case stopped in shaping after decision-check refusals; the stored run recovered after an earlier Intent-format refusal. The candidate used Python bytecode suppression in a test command, showing that part of the instruction appeared in its output, but the observed refusal does not establish a causal effect of either instruction. The evidence-path feedback was not shown to fire in that case. Cause class: unclear (stochastic shaping or candidate effect), with no proven lever-attributable gain. The candidate retained the decision, evidence and readiness gates.

The candidate combined feedback to use one bare tracked path per evidence item with an instruction to avoid transient Python bytecode in generated steps. Both arms used the same model, low effort and no answerer; the control was stored. Times include failed attempts. The shared credit balance did not move visibly; attributable spend is unknown. No held-out or complex requests, Build stage or hidden checks were run. Landing and hidden-check outcomes are unmeasured. Small Go and Node workspaces were reconstructed; byte identity with the earlier study is unverified.

The release uses [Kogen source](https://github.com/KogenAI/kogen/tree/47236bbb93385bc960fd2ac353c9b000bd6ed571) and [shaping source](https://github.com/KogenAI/kogen-shaping/tree/0484edf817f6dc74f691f44d5234cf7f6ae0435e). The candidate adds only the two instructions described above.
