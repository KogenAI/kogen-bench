# Evidence-path guidance before and after rejection

On ten small requests, the stored release reached 6 ready Intents and a candidate reached 7. Two cases changed from not ready to ready and one from ready to not ready. A second unpatched repetition produced exactly the same paired outcomes. The candidate was dropped because its regression fails the registered rule and the net gain does not exceed observed variation. No questions were asked. This is a screen, not a qualified delivery change.

All three discordances occurred in shaping; their cause is unclear because stochastic variation is also observed. In the loss the candidate used bare tracked paths in a recorded decision but then failed a later carried-decisions check; the stored run recovered after an Intent-format refusal. In both gains the stored release ended at the evidence check while the candidate recovered after decision-check refusals. The path instruction is consistent with the form observed in the loss, but the trace does not establish a causal gain. The decision, evidence and readiness gates remained unchanged.

The candidate gave the same guidance both initially and after rejection: use a separate bare inspected tracked path for each file evidence item, without line ranges or prose in the path. Both arms used the same model, low effort and no answerer; the control was stored. Times include failed attempts. The shared credit balance did not move visibly; attributable spend is unknown. No held-out or complex requests, Build stage or hidden checks ran; landing and hidden outcomes are unmeasured. Small Go and Node workspaces were reconstructed; byte identity with the earlier study is unverified.

The release uses [Kogen source](https://github.com/KogenAI/kogen/tree/47236bbb93385bc960fd2ac353c9b000bd6ed571) and [shaping source](https://github.com/KogenAI/kogen-shaping/tree/0484edf817f6dc74f691f44d5234cf7f6ae0435e). The candidate adds only the guidance described above.
