# Lab: why the Rails shapes still refuse after the small-request fix, and the smallest change that gets them through (shaping climb, stage 4)

**Finding.** Stage 3's candidate C6 got small request-only shapes to readiness but its kogen-shaping changes reached readiness on 0 of 5 of the request-only Rails tasks the release is refused on. A model-free reading of those five cells' own events, and a replay of their recorded submissions through the gate functions, show that none of the three later refusals comes from C6's text and none from a wrong gate: (1) the carried-decisions gate checks, in the same submission that records the shaper's decisions, that the Intent already holds each one as an exact ledger line (`(decision: D1, round 1) ...`) that no prompt names; (2) the decision record refuses every command an external coding-agent session ran, while the tool description and the Intent's own evidence rule name `ran` commands as evidence; (3) the last check needs a `controls.json` (a correct implementation and wrong ones) that no prompt names, and its step lines must carry their Gherkin keyword, which neither the form nor the refusal says. C7 adds four text changes to C6 (the decision line and decision evidence named in the shaper prompt and in the external session's note, `controls.json` named as item 4 of the package, and a keyword hint in one refusal line) and changes no accept or refuse decision. On the same five Rails tasks C7 reached readiness on **3 of 5** (C6 0 of 5, the release 0 of 5); on stage 3's held-out small requests it stayed at **10 of 10** (7 at the first attempt). The registered rule (at least 2 of 5, at least 9 of 10, no new refusal class) holds. **Verdict: yes.** The two Rails cells that did not reach readiness show the next walls: writing the correct implementation up front made one first shaper round outlast the 30-minute deadline, and on another the check's eight acceptance runs did not fit its 300-second cap.
## Question

Stage 3 of this climb got small, ordinary request-only shapes to readiness (candidate C6: 20 of 20 small cells) but its kogen-shaping changes reached readiness on 0 of 5 of the request-only Rails tasks the release is refused on: the shapes stopped at three later gates (the decision record, carried decisions, and the wrong-implementation file `controls.json`), two at the 30-minute deadline. Why do these gates refuse, does C6's own prompt text cause any of it, and what is the smallest general change that gets the Rails shapes through without weakening a gate?

- **C7 (this stage's candidate):** C6 plus four text changes and no change to what any gate accepts or refuses (texts verbatim in `data/gate-texts.json`):
  - **D** (shaper prompt): when a submission carries `decisions`, Kogen records each as `D<n>` of the current round and the same submission's Intent must already keep it in `## Decisions` as exactly its line `- <decision> (decision: D<n>, round <r>)` followed by its constraints, evidence, assumption and revision parts and `(source: request)`; decision evidence is files tracked at HEAD that this shaping read; a file the package adds is no evidence.
  - **E** (the note Kogen adds for an external coding-agent session): a command the session ran is no evidence of a submitted decision; cite the files read and put what the command showed in the uncertainty.
  - **K** (shaper prompt, a new item 4): names `controls.json`: when it is needed, that it goes with the first package, its form (a correct implementation and wrong ones, each naming a scenario and the step line that must reject it, keyword included), its limits, that Kogen runs it and the shaper does not, and that it is not Feasibility's observer controls.
  - **G** (gate text only): when a wrong implementation's step is the text of a step of its scenario without the Given/When/Then/And keyword, the refusal line adds "write the step line as acceptance.feature writes it, keyword included: "<keyword> <text>"". Same verdict.
  - C7 is built twice from the same change: on the pin (Kogen 3607552) for the Rails cells, and on kogen-shaping [`0484edf`](https://github.com/KogenAI/kogen-shaping/tree/0484edf817f6dc74f691f44d5234cf7f6ae0435e) (the pin of the adopted release, Kogen [`47236bbb`](https://github.com/KogenAI/kogen/commit/47236bbb93385bc960fd2ac353c9b000bd6ed571)) for the small held-out cells, as in stage 3. The changed files are byte-identical in the two builds.

All cells: Claude Code 2.1.312 with claude-sonnet-5-5 at high effort for shaping, one Mac, shape only, request only, no answers, the login of the subscription seat admitted for that cell.

## Method

1. **Model-free diagnosis.** From the five C6 Rails cells' own shaping events: per attempt the refusing gate, its problem lines, the shaper's round time and tool calls, and what the shaper changed next; each refusal classed (a) the shaper erred and the gate names the form, (b) a prompt or guidance text asks for what the gate refuses, (c) no named way to pass before the refusal. Compared with the release's five stored Rails cells and stage 3's 105 small cells.
2. **Model-free replay.** The recorded submissions of the decision-record, carried-decisions and controls refusals run through the gate functions (a test file in scratch copies of kogen-shaping; no model call) in three trees: the pin, C6 and C7; then with each text change's effect applied mechanically (the decisions with non-file evidence moved into the uncertainty, the Intent lines written from the D sentence's description alone, the controls steps written with their keyword), and with deliberately broken inputs to show the gates still refuse.
3. **Package checks.** kogen-shaping's suite (`go test -count=1 -v ./...`) on C7 against the pin, the prompt goldens regenerated with the package's own `go test -update`.
4. **Cells (registered rule).** C7 on the five Rails tasks (one rep, 1800 s, shape only) and on stage 3's five held-out small requests twice (900 s). C7 passes if it reaches readiness on at least 2 of the 5 Rails tasks (a cell at the deadline counts as not ready), on at least 9 of the 10 held-out small cells, and shows no new refusal class (no refusal from a path C7 changed other than that gate refusing as before, none caused by following a C7 instruction).

The package check of the same submission then runs the carried-decisions gate (`shape/shape.go:1683`, `shape/ledger.go:634-660`), which requires each recorded decision in `## Decisions` as exactly its ledger line (`intentLine`, `shape/ledger.go:209-231`). That line is shown to the shaper only in a later round's context or in this refusal, so the first package that records decisions is refused whatever the shaper writes, unless it guesses the line. No C6 text tells the shaper to drop a decision or mentions the decisions list.
- **Decision record (b).** The decisions tool description (`shape/policy.go:151`) and C6's prompt sentence P name `ran` commands as evidence; the Intent's evidence gate accepts an external session's `ran` command (`shape/evidencemark.go:148`), but the decision record refuses all of them (`shape/ledger.go:470-472`). The shapers cited their own probe runs (as prose or backticked commands) and were refused as "not a file tracked at HEAD". One line (a file the package adds) is (a).
- **controls.json (c).** The wrong-implementation check (`shape/controls.go:757-860`) runs after readiness and a clean contract review and refuses a package without `.kogen/intents/<slug>/controls.json` (`:811`). No prompt names the file (the Feasibility guidance's "observer controls" are a different mechanism), and the external session's note says not to prototype the implementation, which a correct implementation is. Its step match takes the feature line with its keyword (`:171-184`); the form says "<step line>" and the refusal names no fix.

## Verdict: yes

Registered before any measurement (first revision of the Lab record): C7 passes if it reaches readiness on at least 2 of the 5 Rails tasks (one rep; a cell at the 1800 s deadline counts as not ready), on at least 9 of 10 held-out small cells, and shows no new refusal class (no refusal from a path C7 changed other than that gate refusing as before, none caused by following a C7 instruction).

- **Rails tasks: holds.** 3 of 5 (needs 2); C6 and the release 0 of 5.
- **Held-out small requests: holds.** 10 of 10 (needs 9), 7 at the first attempt.
- **No new refusal class: holds.** C7's refusals are decision-check lines (a kind the release shows), one Intent-lint line about a Stages section no C7 text mentions, and one wrong-implementation time cap: a pin gate on a path C7 does not change that refuses the same controls the same way in the pin, met only because C7's package now reaches the runs. The one problem line C7 changed was never met.

What each change rests on: K (`controls.json` named) on the cells, every submitted first package carried the file and two passed the check at once where C6 was refused for its absence; D, E and G on the model-free replay only, because no C7 cell used a decisions list or met the keyword refusal.

## Deviations and limits (plain)

1. **One rep per task.** Shaping is stochastic (earlier screens measured 18 to 27 percent of paired cells flipping with identical arms); counts, no significance claim. On one task the contract review named no checked property in the C7 cell, so that task's readiness does not test K.
2. **The cost of naming controls.json.** The first shaper round grew on every Rails task (from C6 to C7: 425 to 497 s, 763 to 804 s, 785 to 1402 s, 474 to 940 s, and 1108 s to more than 1800 s), because the shaper writes a correct implementation, and runs it, before the first submission, although the text says Kogen runs it. One task ran out of time inside that round.
3. **The 300 s cap.** The wrong-implementation check needs at least one wrong implementation per checked property and runs the whole acceptance once per implementation; with seven properties on a slow Rails suite, eight runs did not fit in 300 s. Not changed here.
4. **No ablation run.** The replay names no C6 piece as the cause of a refusal, so the allowed model run for a piece's ablation was not spent; whether C6's text makes shapers use the decisions list more (2 of 5 C6 Rails cells, 0 of 5 release Rails cells, none of the 14 C7 cells that submitted) is not separated.
5. **Small repositories rebuilt.** Stage 3's scratch repositories were deleted with its run trees; they were rebuilt from its published description and creation commands, with its check strings (the Node check `node --test test/` fails under Node 24, as it did there; shaping does not run it).
6. **Two builds of one change.** The Rails cells ran C7 on release 3607552 (where the refusals were measured), the small cells on the adopted release 47236bbb, as stage 3 did; the changed files are byte-identical. Rebuilding C6 here gave stage 3's binary except for build-path identifiers.
7. **Cost** is the coding agent's reported list-equivalent figure on subscription seats (15.66 USD reported in all, plus one unreported first round).
