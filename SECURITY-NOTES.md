# Security notes

## Publication identity and upstream contents

Git commit metadata intentionally retains the author identity **Almir Sarajčić <almir.sarajcic@icloud.com>**. This is the same public identity used on his other public KogenAI repositories; it is retained as repository authorship metadata.

Upstream code and benchmark files from 37signals LLC's Fizzy, Fizzy SaaS, and Writebook, and from Agents on Rails (commissioned by the Rails Foundation and built by Evil Martians), are redistributed as their authors published them. Their contents remain upstream-authored, including upstream hostnames, deployment paths, public addresses, commit identities, and test fixtures such as DNS test IPs. These values are covered by the upstream credits and notices and are not Kogen machine or account data. No upstream source files were changed during the publication cleanup.

Kogen-produced artifacts had local execution leftovers removed. The hard2 Fizzy snapshot bundle no longer contains `log/` or `tmp/` (including Bootsnap caches), and one archived patch now uses a portable minitest require in place of a workstation-specific absolute path. [PUBLICATION-MANIFEST.json](PUBLICATION-MANIFEST.json) records each as-run hash next to its published hash, the rebuilt bundle commit/tree, and the change rationale.

The Phoenix values occur only in sealed task fixture configurations, including base, reference, and negative examples. The fingerprint manifests contain SHA-256 source-file digests that match the generic rule by shape. The Rails password is used in a test request for a fixture user. The Web Push values are upstream test key material in retained Rails test changes and are tied to the public test endpoint fixture. These are synthetic/test-only values, not production or service credentials.
