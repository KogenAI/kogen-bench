# Diagnosis

The violated fixed property is `admission_iff`: start must set `admitted`
exactly when `approved == revision` (contract.md and laws.json). The causal
function is `Workflow.admission/1`, app/lib/workflow.ex:48–50. Its current
expression, `state.approved != :none`, tests only whether any approval exists,
ignoring which revision was approved. `step/2` dispatches start through
`dispatch/2` and `start/1`, which writes that helper's result into `admitted`.

Before any application patch, complete check cycle 1 (`./fv check`) regenerated
the current formal representation and exited 1: `approval_binding` and `edit`
passed, `admission_iff` failed, and the starter test passed (1 test).
Lean reported that `decide` proved `check_admission_iff = true` false. The
source trace includes the start dispatch, `start/1`, and `admission/1`, ending
at the defective expression on line 49. This check did not print a concrete
`FV-COUNTEREXAMPLE` line; the following witness is derived directly from the
application and lies within the fixed six-event bound:

- Initial state: revision r1, approved none, admitted false.
- approve: revision r1, approved r1, admitted false.
- edit_r2: revision r2, approved r1, admitted false.
- start: the current helper yields true because r1 != none. The contract
  requires false because r1 != r2.

This is an implementation defect, supported by a reachable concrete mismatch
and the false Lean proposition, rather than an unresolved proof or tooling
limitation. The starter test misses historical approval after a revision edit.

The repair will compare `state.approved == state.revision` in `admission/1`,
preserving all public functions and the existing approval/edit behavior.
Regression coverage will reject stale approvals in both revision directions
and confirm that selecting the approved revision again restores admission
on the next start. Fixed laws, domains, assumptions, and bounds will remain
unchanged. The supplied checker will regenerate formal representations from
the changed Elixir application and rerun fixed laws and starter tests.
