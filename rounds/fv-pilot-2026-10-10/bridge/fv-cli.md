# Shared feedback CLI contract

Package root contains `app/`, `contract.md`, `laws.json`, `bridge/`, `fv`, and
the arm's checked verification package under `verification/`.
Invocation: `./fv check`, no network, as bench. Both arms run the same stages:

1. Validate fixed laws.json and backend law-file hashes from `fixed.sha256`.
2. Parse CURRENT app/lib source with the common frontend into generated IR.
3. Emit CURRENT backend definitions and source map. Never overwrite fixed laws.
4. Run backend verification, printing law names and source-connected diagnostics.
5. Run `mix test` starter tests even when a law fails (unless translation failed).
6. Print exactly one summary:
   `FV-SUMMARY arm=lean laws_ok=3/4 tests_ok=true regenerated=<sha256>`
   (`arm=quint` in the other arm).

`regenerated` hashes IR plus generated implementation, not a stale formal copy.
`laws_ok` counts fixed laws successfully checked. `tests_ok` is lowercase boolean.
Exit 0 only when regeneration, all laws, hash checks and tests pass. Exit 1 for
violated laws/test failures; exit 2 for unsupported source, changed fixed laws,
missing tools or checker infrastructure failure. Print an explicit reason.
Raw output is retained by the harness. No catalog, oracle, alternate repair or
reference source belongs in a package. Both arms use identical domains/bound.

## Optional root-broker packaging adapter

The `harness/package.py` uses `backend/` as the verification directory and
requires `bridge/<arm>/packages/<TASK>/fv-backend.json` with immutable
`regenerate`, `check`, `starter` argv arrays. The Quint adapter executes the same
stages above through `backend/stage.py regenerate|check|starter`; its final stage
prints the same `FV-SUMMARY arm=quint ...` line. The standalone CLI template
continues to use `bridge/` and `verification/`. Initial qualification metadata
contains no reference source or counterexample from sealed variants.

The broker adapter also requires `docs/<arm>/DOCS.json` with
`"scope": ["language", "verification"]`. `harness/package.py` compares offline
documentation sizes (maximum 2× ratio), and requires public-api.json/title.txt
from the fixture builder. These are assembly interfaces; they do not change
the checker stages or the accepted laws. Quint's offline notes are in
docs/quint, and runtime bundles will be generated by bridge/quint/package.py.
