# Race 6 token extraction

For each arm, deduplicate every thread_id from out/<arm>/turn-*.jsonl thread.started events, then sum each thread’s cumulative total_token_usage at its last token_count event at or before the host epoch + 3,600 s (Studio 07:28:00Z; MacBook 07:26:00Z on 2026-10-11); this is cumulative usage at the last token event before the kill, not a turn.completed sum.

Token extraction used the retained Mac Studio and MacBook run directories and their corresponding local session archives. Personal directory and account names are omitted.
Epochs are 2026-10-11T06:28:00Z (Studio) and 2026-10-11T06:26:00Z (MacBook), as recorded in the existing results.

`collect_tokens.py` filters raw JSONL lines for unescaped allowed event markers before JSON decoding. From turn files it retains only `thread.started.thread_id`. From rollouts it retains only session `id`/`cwd`, token timestamps and the five `payload.info.total_token_usage` integers. Other transcript records are skipped without JSON decoding and are never printed, copied or persisted. No auth files are read. The only network operation is read-only `ssh MacBook`, running the collector as a Python `-c` one-liner; no remote files are created. SSH stdout contains only allowed token counts/timestamps, session id/cwd metadata, and their derived summaries.

Thread ids are deduplicated per arm. Each id must match exactly one rollout filename recursively within that host’s sessions directory. Session id and cwd must agree with the thread id and arm directory. Token timestamps are parsed with timezone offsets and must be nondecreasing; selection uses the latest timestamp at or before the inclusive kill cutoff, with the last file occurrence breaking timestamp ties. Events without total usage are skipped. A missing thread, rollout, metadata match or eligible usage causes extraction to fail rather than inserting zero. If an arm has several threads, the five selected cumulative counts are summed, `n_threads` counts unique ids, and the TSV timestamp is the latest selected timestamp among those threads. Thread-level selected timestamps are retained in the sanitized JSON for audit.

All 16 arms have exactly one unique thread, one matching rollout, matching session metadata, and eligible cumulative usage. There are 1,905 eligible token events and 0 later token events excluded. Selected events precede kill by 2.132–38.214 seconds. The unfinished interval between the selected event and kill has no later eligible token record and is not estimated.

`build_tokens.py` writes the 16-row `tokens.tsv`, sanitized JSON, and one Markdown table with 16 arm rows and eight language/condition median rows. Each median is the arithmetic mean of the two host counts, independently for each field; fractional medians are retained. Cached input is a subset of input, and reasoning is a subset of output: neither is added again to total. Every arm passes `total = input + output`, `cached_input <= input`, and `reasoning <= output`. These are cumulative processed token counts, including repeated and cached input across model requests, rather than unique transcript length.

The recovered table is now present in RESULTS-R6.md and the source results JSON. This bundle projects the 16 aggregate token rows to results/tokens.tsv and cells.tsv, and retains the per-language/condition medians in the README token table. Completed-turn usage remains absent; it is a separate receipt type and does not negate recovered session-rollout usage. No thread IDs, raw rollouts or account/session payloads are published.
